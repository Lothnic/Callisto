The problem

Give Agents A Clearer View.

Perception 001

Pages Carry A Lot Of Context

Raw markup can be large and difficult to navigate. A task may need only a small part of the page.

Action 002

Pages Keep Changing

Elements move, disappear, or become covered. An action needs to check the page as it exists now.

Setup 003

Trust 004

A useful response makes it easier for the agent to inspect the page and decide what to do next.

Introducing Callisto

Your Agent.
A Real Browser.

Callisto runs a local Chromium and exposes it over MCP. The agent navigates, reads a bounded accessibility tree, and acts on page refs — without a separate Playwright install or model API key.

THE LOOP / 01

Connect an MCP host.

Callisto speaks stdio MCP. OpenCode, Claude Code, Codex, or your own host launches one process. The host supplies the model; Callisto requires Node.js and a local Chromium or Chrome binary.

THE LOOP / 02

The page becomes a short, structured tree.

A pruned accessibility snapshot, actionable nodes first, bounded to 12,000 characters. Refs look like ax-12. callisto_find searches the rest.

THE LOOP / 03

Refs, roles, and batches.

Click a ref, fill by role, press a chord, or send up to ten actions in one call. Same-origin frames are supported; cross-origin frames fail closed.

THE LOOP / 04

Inspect the resulting page.

Navigation and action tools return a fresh snapshot so the agent can inspect the result before continuing.

The difference

Less Context.
Sharper Actions.

Give the agent the page it needs to act on, not the markup the browser happened to build.

01

See the page, not the markup.

A pruned accessibility tree keeps roles, names, state, and values. Scripts, styles, and wrapper divs stay out.

02

Act on refs, not guesses.

Click and fill check visibility, stability, enabled state, and hit testing before they touch the page.

03

Bound the context.

Snapshots default to 12,000 characters. Page with nextOffset or search the full tree with callisto_find.

Get started

From Repository
To Browser.

  1. 01 / BUILD

    Install the engine.

    For isolated Chromium, install Git, Node.js 20+ and Chrome or Chromium, then run the installer. For existing Zen or Firefox tabs and other hosts, follow the user and agent setup guide.

    The installer builds a pinned Chromium revision. For Zen or Firefox, use the source setup in the guide.

    curl -fsSL https://callisto.lothnic.dev/install.sh | bash
  2. 02 / REGISTER

    Add the MCP server.

    The installer prints your exact command and path. Add it to your MCP host’s configuration; adapt this example for your host.

    {
  "mcpServers": {
    "callisto": {
      "command": "node",
      "args": ["/absolute/path/to/callisto/packages/mini/dist/mcp.js"]
    }
  }
}
  3. 03 / ASK

    Give it a task.

    The first browser call starts an isolated session. Set CHROME_PATH if your browser is not discovered.

Questions

Before You Install

01 Is this Playwright?

No. Callisto is a CDP engine with a Playwright-shaped subset. It exposes structured MCP actions, not arbitrary JavaScript. Treat it as a lean runtime, not a drop-in Playwright replacement.

02 Does it use my browser or my logins?

Mini starts isolated Chromium by default; its experimental browse connection opens an agent-owned tab in your existing profile. The separate experimental Firefox and Zen bridge can control existing tabs and logins after pairing and permission. It uses a temporary extension and has capability limits. Read Firefox and Zen setup ↗

03 Do I need a model API key?

No. Your host agent supplies the model. Callisto only supplies the browser and the page representation.

04 How big are the snapshots?

MCP snapshots default to 12,000 characters. Use nextOffset to page through the last capture, or callisto_find to search the full tree without sending all of it.

05 Is it safe to run unattended?

Callisto is not a sandbox. Browser actions can change real websites, and snapshots are not a general secret filter. Use a dedicated profile and your own approval layer for sensitive work. The experimental connected mode requires an origin allowlist; it does not block all subresources.

06 What is actually shipped today?

The CDP engine, the MCP server, bounded snapshots, same-origin frame actions, batching, and an eval kit. Cross-origin frames, toolbar take-back, and full Playwright compatibility are still open work. The project is experimental and says so.
